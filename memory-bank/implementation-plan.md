# 人员管理与绩效考核系统 - AI开发者实施计划

## 文档说明

本文档为AI辅助开发提供分步实施指南。每个步骤都经过精心设计，确保：
- **小而具体**：每步专注于单一任务，避免复杂性
- **可验证**：每步都有明确的测试方法验证正确性
- **无代码**：只提供清晰的指令，代码由AI生成
- **渐进式**：先构建基础系统，再扩展完整功能

### 全局规范与修订
- 角色与权限：MVP阶段创建5个角色（总监/副总监、项目负责人、参与人员-售前、参与人员-研发、HR/财务）。roles.permissions字段采用字典结构JSON存储，包含模块权限与数据范围：
  - 示例：
    ```json
    {
      "modules": {
        "project": ["create", "update", "delete", "view", "workhour_record", "contribution_calculate", "progress_manage"],
        "key_task": ["create", "update", "delete", "view", "complete", "settle"],
        "penalty": ["create", "update", "view", "confirm", "settle"],
        "settlement": ["generate_monthly", "view", "export", "confirm"],
        "user": ["view", "manage_roles"],
        "system_config": ["view", "update"]
      },
      "data_scope": "all"  // all | department | own
    }
    ```
- 项目节点与权重：默认节点为11个（不包含“维保结束”）。后端以0–1小数存储与校验，前端以百分比展示；权重总和校验按0–1进行。
  - 默认11节点列表：商机、项目建议书、可研、招投标、前向签约、系统研发、后向采购、后向签约、项目试运行、初验、终验。
- 错误码与异常：参数校验=400，业务错误=400或422，系统异常=500；资源不存在统一返回HTTP 404并使用统一Result包装。
- 认证与安全：JWT算法HS256，支持刷新token与黑名单（登出/强制下线）；Redis用于缓存与token黑名单/会话。开放/login、/health、/swagger-ui.html、/v3/api-docs在开发环境；生产环境限制swagger访问。
- token过期策略：前端基于exp进行校验；存在刷新token流程，刷新失败自动重登。
- 时间与时区：MySQL与应用时区统一为Asia/Shanghai（serverTimezone=Asia/Shanghai），后端日期格式统一使用ISO 8601（例如：2026-02-09T12:30:00+08:00）。
- 计算规则与精度：CPj计算保留4位小数（HALF_UP）；前端展示为百分比保留3位；总和容差允许0.0001；未完整填报节点时可计算，未填报节点LCi默认为0。
- 业务校验：项目编号格式固定为PROJ-YYYY-XXX（XXX为000–999，大写），年+序号复合唯一；按岗位切分时presale_ratio与rd_ratio允许边界0或1但总和必须=1；PositionType与中文映射（PRESALE=售前，RD=研发）。
- 前端约定：路由守卫除检查localStorage外需调用后端校验token有效性；前端基于角色隐藏菜单与按钮（MVP实现）。

**任务描述：**

**验证方法：**
- 登录获取access/refresh token，验证两者时效
- 使用refresh token获取新access token
- 登出后旧access token访问返回401
- 关闭Redis后系统仍可运行（禁用黑名单校验或降级），记录警告日志

实现月度结算的核心计算逻辑。

**Service方法：**
- generateMonthlySettlement - 生成指定月份的结算
- 计算逻辑：
  1. 查询该月结束的所有项目，计算每个人的项目虚拟利润
  2. 查询该月办结的重点事项，汇总补贴
  3. 查询该月确认的惩罚事项，汇总扣款
  4. 计算：虚拟总收入 = 项目虚拟利润 + 重点事项补贴 - 惩罚扣款
  5. 应用兑换系数计算实际绩效奖金
- 为每个人生成一条结算记录
- 保存贡献明细

**验证方法：**
- 准备测试数据：
  - 创建1个项目并填报工时（2个参与人员）
  - 为这2个人创建重点事项并办结（各500元补贴）
  - 为其中1个人创建惩罚记录（扣款200元）
  - 设置项目虚拟工时为1000小时
  - 设置兑换系数为1.0
- 调用生成结算方法
- 验证人员A：项目虚拟利润（假设贡献度10%）= 100小时，重点事项补贴 = 500，惩罚扣款 = 200，虚拟总收入 = 400小时，实际奖金 = 400元
- 验证人员B：项目虚拟利润（假设贡献度15%）= 150小时，重点事项补贴 = 500，虚拟总收入 = 650小时，实际奖金 = 650元
- 验证数据库中有2条结算记录

## 附录：AI提示词最佳实践

### 使用指南

在向AI请求生成代码时，请遵循以下最佳实践：

**1. 明确上下文**
```
我正在开发人员管理与绩效考核系统。
技术栈：后端Java 17 + Spring Boot 3.2，前端Vue 3 + Element Plus。
当前任务：步骤X.X.X - [任务描述]
```

**2. 引用技术栈文档**
```
请参考tech-stack.md文档中的规范：
- 使用MyBatis-Plus
- 实体类使用Lombok注解
- 统一响应格式Result<T>
```

**3. 引用设计文档**
```
数据库表结构参考manager-design-document.md第4.2节。
业务规则参考第5.1节项目贡献度计算流程。
```

**4. 明确输入输出**
```
请生成UserService接口的login方法：
输入：String username, String password
输出：LoginResponse（包含token、userId、username、roleName）
异常：用户不存在或密码错误抛出BusinessException
```

**5. 要求验证代码**
```
请同时生成单元测试代码，测试场景：
1. 正确的用户名密码登录成功
2. 错误的密码抛出异常
3. 不存在的用户抛出异常
```

**6. 分步实施**
```
不要一次生成整个模块，而是：
1. 先生成实体类User
2. 然后生成UserMapper接口
3. 再生成UserService接口
4. 最后生成UserServiceImpl实现类
每步都验证编译通过后再继续
```

**7. 明确代码风格**
```
代码要求：
- 所有字段添加中文注释
- 方法添加JavaDoc注释
- 使用Lombok减少样板代码
- BigDecimal处理金额，保留2位小数
- LocalDateTime处理日期时间
```

本实施计划提供了一个清晰的路线图，从基础系统到完整功能的渐进式开发。关键成功因素：
