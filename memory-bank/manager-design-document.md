# 人员管理与绩效考核系统设计文档

## 1. 系统概述

### 1.1 项目背景
本系统旨在建立一套完整的人员管理和绩效考核体系，通过量化项目贡献、日常重点事项和惩罚机制，实现公平、透明的绩效评估和虚拟利润分配。

### 1.2 核心目标
- 记录和管理项目全生命周期的工时和贡献度
- 追踪和结算重点事项补贴
- 记录和处理惩罚事项
- 自动计算个人项目贡献度和虚拟利润
- 支持月度、年度绩效结算

### 1.3 核心设计思想
系统通过预设规则自动计算个人贡献度/奖惩，最终汇总为绩效或虚拟利润提成基础。所有操作均需留痕，确保数据可追溯、可审计。

## 2. 人员架构设计

### 2.1 角色定义

#### 2.1.1 总监/副总监
**职责：**
- 发布和管理重点事项
- 评定项目总体工时和虚拟利润
- 确认项目最终贡献度分配
- 发起和确认惩罚事项
- 评估历史项目和政治性项目的虚拟工时

**权限：**
- 创建、编辑、删除重点事项
- 审批项目贡献度
- 设置虚拟利润兑换系数
- 查看所有人员绩效数据
- 修改系统配置参数

#### 2.1.2 项目负责人
**职责：**
- 创建和管理项目
- 设置项目贡献度分配方式
- 填报和更新各节点工时
- 确认参与人员及其贡献度
- 设置项目月度预期进度
- 提交项目最终数据供总监审核

**权限：**
- 创建项目
- 编辑所负责项目的信息
- 分配项目参与人员
- 填报工时数据
- 提交项目结算申请

#### 2.1.3 参与人员（售前/研发）
**职责：**
- 确认个人工时记录
- 确认个人贡献度分配
- 办结分配的重点事项
- 查看个人绩效数据

**权限：**
- 查看参与项目的工时记录
- 确认个人贡献度
- 提交重点事项办结

**岗位分类：**
- **售前人员**：主要参与商机、项目建议书、可研、招投标、前向签约等前期节点
- **研发人员**：主要参与系统研发、项目试运行、初验、终验等技术实施节点

#### 2.1.4 指定人员（HR/财务）

- 接收项目最终确认数据

## 3. 功能模块设计

### 3.1 项目管理模块

#### 3.1.1 项目生命周期节点
系统预定义11个项目节点（不包含“维保结束”），每个节点在整个项目中的权重可配置：

1. **商机** - 客户需求识别和初步沟通
2. **项目建议书** - 解决方案初步设计
3. **可研** - 可行性研究
4. **招投标** - 投标文件准备和参与竞标
5. **前向签约** - 与客户签订合同
6. **系统研发** - 技术开发和实施（通常占比最高）
7. **后向采购** - 采购所需资源和设备
8. **后向签约** - 与供应商签订合同
9. **项目试运行** - 系统测试和试运行
10. **初验** - 初步验收
11. **终验** - 最终验收

**配置要求：**
- 各节点权重（LPi）之和必须等于100%
- 默认权重可由系统预设，项目创建时可调整
- 权重一旦项目开始不建议频繁修改，需总监审批

#### 3.1.2 贡献度分配方式

**方式一：按岗位比例切分**
- 适用场景：售前和研发职责明确分离的项目
- 配置参数：
  - 售前比例（S）：如30%
  - 研发比例（D）：如70%
  - S + D = 1
- 计算规则：
  - 售前人员：CPj = S × ∑(LPi × LCi,j)
  - 研发人员：CPj = D × ∑(LPi × LCi,j)

**方式二：共同分配**
- 适用场景：团队协作紧密，职责交叉的项目
- 配置参数：所有人员岗位划分比例 R = 1
- 计算规则：CPj = ∑(LPi × LCi,j)

#### 3.1.3 工时管理
**工时填报流程：**
1. 项目创建时，项目负责人预设各节点参与人员和预估工时
2. 项目进行中，按月更新实际工时
3. 每月设置项目预期进度
4. 项目结束时，由项目负责人确认最终工时
5. 总监审核并评定总体虚拟工时
6. 发送给参与人员确认
7. 数据留痕并发送至HR/财务

**工时字段：**
- 节点名称
- 参与人员
- 预估工时（小时）
- 实际工时（小时）
- 贡献度占比（LCi,j）
- 填报时间
- 确认状态

#### 3.1.4 特殊项目处理
- **历史项目**：无收入但需计入贡献度的已完成项目
- **政治性项目**：为政府或重点客户提供的公益性项目
- **重点客户额外支撑**：未纳入其他项目的特殊支持工作

处理方式：总监评定虚拟工时作为虚拟利润基数进行提成

### 3.2 重点事项管理模块

#### 3.2.1 事项类型

**一次性任务**
- 创建后由责任人办结即完成
- 办结后自动标记为已完成
- 不再重复出现

**周期性任务**
- 按月循环
- 当月办结后，次月自动重新生成
- 需高权限人员手动终止

#### 3.2.2 补贴计算规则

| 事项类型 | 补贴标准 | 结算周期 |
|---------|---------|---------|
| 展会/培训支撑 | 工作日100元/天，非工作日200元/天，节日300元/天 | 当月 |
| 人力事务支撑 | 300元/月 | 当月 |
| 采购任务 | 300元/项 | 完成后当月 |
| 工会党务活动 | 500元/年 | 年末 |
| 技发薪酬立项流程 | 500元/月 | 当月 |
| 研发立项全流程 | 300元/月 | 当月 |
| 研发云平台上云 | 300元/个 | 当月 |
| 申报材料编写 | 300元/个（获奖后另行分配） | 当月 |
| 护网支撑 | 工作日100元/天，非工作日200元/天，节日300元/天 | 当月 |

#### 3.2.3 流程设计

```
总监发布重点事项
    ↓
责任人接收任务通知
    ↓
责任人执行并填写完成情况
    ↓
责任人提交办结申请
    ↓
总监确认办结
    ↓
系统自动计算补贴金额
    ↓
计入当月结算
```

### 3.3 惩罚事项管理模块

#### 3.3.1 惩罚类型

**系统故障**
- 记录故障级别、影响范围、持续时间
- 由总监根据规则或个案评定扣款金额
- 需要责任认定和原因分析

**网信安事件**
- 严格惩罚：扣款 = 直接经济损失 × 10%
- 需要详细记录损失金额和责任人
- 重大事件需要事件报告

#### 3.3.2 处理流程

```
总监发起惩罚事项
    ↓
填写事件详情（时间、原因、损失、责任人）
    ↓
计算扣款金额
    ↓
通知责任人并要求确认
    ↓
责任人确认或申诉
    ↓
总监最终裁定
    ↓
计入当月结算
    ↓
数据留痕
```

### 3.4 绩效结算模块

#### 3.4.1 虚拟利润计算

**项目虚拟利润池**
- 项目结束后，总监评定"总虚拟工时"作为该项目价值基数
- 虚拟工时可基于：项目规模、技术难度、重要程度、实际收益等

**个人项目所得**
```
个人项目虚拟利润 = 项目总虚拟工时 × 个人该项目贡献度(CPj)
```

**月度总收入**
```
个人月度虚拟总收入 = ∑(个人各项目虚拟利润) + ∑(重点事项补贴) - ∑(惩罚事项扣款)
```

**实际绩效奖金**
```
实际绩效奖金 = 个人月度虚拟总收入 × 虚拟利润兑换系数
```

#### 3.4.2 结算周期

**月度结算**
- 重点事项补贴（当月结算类）
- 惩罚事项扣款
- 当月结束的项目虚拟利润

**年度结算**
- 工会党务活动补贴
- 年度奖励
- 获奖后另行分配的部分

## 5. 核心业务流程

### 5.1 项目贡献度计算流程

```
┌─────────────────────────────────────────────────┐
│ 1. 项目创建                                      │
│   - 选择分配方式（按岗位切分/共同分配）           │
│   - 设置售前/研发比例（如30%:70%）               │
│   - 配置各节点权重（LPi，总和=100%）             │
└─────────────────────┬───────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────┐
│ 2. 工时填报（项目进行中）                         │
│   - 项目负责人按节点填报参与人员                  │
│   - 填写每人在该节点的实际工时                    │
│   - 确定每人在该节点的贡献度占比（LCi）           │
│   - 各节点参与人员的LCi之和=100%                 │
└─────────────────────┬───────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────┐
│ 3. 参与人员确认                                   │
│   - 系统通知参与人员                              │
│   - 人员查看并确认自己的工时和贡献度              │
│   - 确认后数据锁定                                │
└─────────────────────┬───────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────┐
│ 4. 项目结束与总监评定                             │
│   - 项目负责人提交项目结束申请                     │
│   - 总监评定项目总虚拟工时（虚拟利润基数）         │
│   - 总监审核并确认最终贡献度分配                   │
└─────────────────────┬───────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────┐
│ 5. 贡献度计算                                     │
│   对于每个参与人员j：                              │
│   - 计算原始贡献度 = ∑(LPi × LCi,j)               │
│   - 应用岗位比例：CPj = R × ∑(LPi × LCi,j)        │
│     * 按岗位切分：R = S（售前）或 D（研发）        │
│     * 共同分配：R = 1                             │
│   - 验证：所有人的CPj之和 = 1                     │
└─────────────────────┬───────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────┐
│ 6. 虚拟利润分配                                   │
│   个人项目虚拟利润 = 项目总虚拟工时 × CPj         │
└─────────────────────┬───────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────┐
│ 7. 数据留痕与结算                                 │
│   - 数据发送至HR/财务                             │
│   - 计入当月或对应月份结算                         │
│   - 归档审计                                      │
└─────────────────────────────────────────────────┘
```

**计算示例：**

假设某项目采用按岗位切分方式，售前比例S=30%，研发比例D=70%。

节点权重设置：
- 招投标：5%
- 前向签约：10%
- 系统研发：50%
- 初验：20%
- 终验：15%

参与人员A（售前）：
- 招投标节点贡献度：60%
- 前向签约节点贡献度：30%

计算A的贡献度（CP_A）：
1. 招投标部分：5% × 60% = 3%
2. 前向签约部分：10% × 30% = 3%
3. 原始贡献度小计：3% + 3% = 6%
4. 应用售前比例：CP_A = 6% × 30% = 1.8%

若项目总虚拟工时评定为1000小时，则：
- A的虚拟利润 = 1000 × 1.8% = 18小时

## 8. 安全性设计

### 8.1 认证与授权
- **身份认证**：支持账号密码登录、SSO单点登录
- **会话管理**：JWT（HS256）+ Redis缓存
- **Access/Refresh双Token**：提供`POST /api/auth/refresh`刷新接口
- **黑名单机制**：登出`POST /api/auth/logout`将Access Token加入Redis黑名单并在拦截器校验
- **权限验证**：每个接口调用都进行权限检查
- **密码策略**：强制复杂度要求、定期更换

### 8.2 数据安全
- **敏感数据加密**：密码使用bcrypt加密存储
- **传输加密**：全站HTTPS
- **SQL注入防护**：使用参数化查询
- **XSS防护**：前端输出转义
- **CSRF防护**：Token验证

### 8.3 操作审计
- 所有敏感操作记录审计日志
- 日志包含：操作人、时间、IP、操作内容、前后数据对比
- 日志定期归档，至少保留3年

### 8.4 时间与格式
- 统一时区：Asia/Shanghai（数据库serverTimezone与应用Jackson）
- 时间格式：后端统一ISO 8601（含时区偏移）

## 12. 风险与应对

### 12.1 技术风险

**风险：性能问题**
- 场景：大量用户同时访问，计算贡献度时数据量大
- 应对：
  - 采用缓存机制
  - 异步计算
  - 数据库索引优化
  - 分库分表预案

**风险：数据准确性**
- 场景：复杂的计算公式可能出现错误
- 应对：
  - 充分的单元测试和集成测试
  - 计算结果人工抽查验证
  - 提供计算过程详细日志
  - 设置校验规则（如总贡献度必须等于1）

### 12.2 业务风险

**风险：规则频繁变更**
- 场景：考核规则、补贴标准可能调整
- 应对：
  - 规则配置化，支持灵活调整
  - 规则版本管理
  - 历史数据兼容处理

**风险：用户接受度**
- 场景：用户可能不习惯新系统
- 应对：
  - 充分的用户培训
  - 操作手册和视频教程
  - 设置过渡期
  - 收集反馈持续优化
